## Where Surface is already ahead

None of the 33 repos has any of these:
- a server-authoritative window manager that the agent, palette, CLI and MCP all drive the same way;
- context selected from the situation (slots with live Knowledge and per-slot notes);
- reflexes with focus and event triggers that a layout switches on;
- agent-to-owner overlays, and step guides that wait for owner actions;
- ways of working saved as versioned layouts (Interaction Builder).

None of them uses real intent classification to pick context. The closest:
- anything-llm: a sticky LLM router with a cooldown on no-match;
- omnigent: a gate between trivial and non-trivial requests;
- happier: sorts requests into 4 modes (question, change order, exploration, thinking aloud);
- paperclip and openrig: a typed `decide()` service, advisory only.

A classifier-driven Selector would be new among them. Their generated UI is mostly fixed renderers or free iframes; Surface's reviewed patterns, with immutable snapshots and a journal, are the most rigorous of the set.

## Where they are ahead (ranked by value to Surface)

### 1. Window provenance and desk etiquette
`desk.Win` had no opener, owner or retention, and close popped a global trail.
- Orkas web-assist: tabs carry a retention (temporary, deliverable or handoff), and a tab the user takes over is promoted to theirs.
- herdr: open with `--no-focus`, split beside the caller, never close panes you did not create.
- t3code: tabs have owners.
- marq: origin backlinks.
- omnigent: `ui_open_file` respects unsaved-edit guards.
- vaquita and tortie: written lists of "rules the app keeps".
- Counter-examples: stagewise steals focus (`setActive:true`); openhuman falls back to the first tab on close.

### 2. A single attention model
From tortie, dure, happier, herdr, KLIDE, marq, ruflo-console, zerus and moai:
- one status vocabulary;
- seen-ness as server state, counted only when visible and focused;
- notifications suppressed for whatever is in focus, and bursts coalesced;
- a cap on banners, with severity eviction;
- a "next up" jump;
- resolvable items kept apart from terminal facts;
- the owner's own input never raises attention.

### 3. Input semantics
From bb, omnigent, openhuman, happier, LoopForge, openrig and agent-orchestrator:
- steer, queue and interrupt as distinct actions;
- stop holds the queue;
- draft-aware delivery;
- a stall banner;
- a `/btw` side-chat fork.

### 4. Card lifecycle
- End-of-turn offers or next-actions (podium, marq).
- Supersede-on-comment: if the owner types instead of answering, the card lapses (paperclip).
- Edit-before-approve, and hold-on-engage (anything-llm).
- Hash-bound approval of the exact snapshot (open-multi-agent, zerus).
- Lapse tied to state, not only the clock (LoopForge).
- Unanswered is not declined (ai-bwrap).
- Approve means run (paperclip).
- A per-turn budget for questions.
- A blocked-on-you cascade (openrig, munder-difflin).
- Multi-question cards with option previews (bb).
- A review-dwell timer (zerus).

### 5. Context assembly
- Snapshot once, then send only the changes (stagewise).
- An assembly trace (cradle) and a "Why is this in context?" inspector (moai).
- Explicit attachments outrank implicit focus.
- Ambient dwell observations.
- Sticky selection with a no-match cooldown (anything-llm).

### 6. The classifier's data loop
- Decision snapshots (paperclip).
- Implicit signals (Orkas): silence for 30 minutes counts as acceptance, a form left blank, a skill that did not help.
- happier's 4 request modes as a first classifier head.
- The owner's re-pins as free labels.
- Request origin and authority (zerus).

### 7. Agent-authored ways of working
- Propose-only activation (openhuman).
- Change set, then partial apply, then undo (superplane).
- Constrained patches from run evaluation (LoopForge).
- A recursion guard (bb).
- Restorable defaults.

### 8. Default reflex families
- A loop and drift monitor, escalating steer, then constrain, then stop (KLIDE, munder-difflin).
- Auto-retry for classified errors (zerus).
- Watches and agent self-follow-ups (openrig, marq).
- Durable awaits (cradle).
- Triggers on tool-result state (Bindu).
- Armed-not-run for risky commands (tortie).

### 9. Generated UI additions
- A next-actions card.
- A sandboxed visual with a screenshot self-check (bb, t3code).
- A report kit restricted to theme tokens, with buttons that send a prompt back (cradle, Orkas).

### 10. Owner-to-agent pointing
The mirror of `ade_point`: Pinpoint (dure), element annotation (bb, LoopForge, stagewise), and select-then-ask in a side chat.

### 11. Tool surface hygiene
- Per-surface exposure and a discoverable-only tier (happier ActionSpec; t3code toolSearch and alwaysLoad).
- Evals over tool wording (t3code).
- Typed partial or unknown answer envelopes (ye-ast).
- Spilling large results to a window.
